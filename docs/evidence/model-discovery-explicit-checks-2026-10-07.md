# 模型目录与明确调用检查：取消隐式推理

2026-10-07。本次修正服务于模型中立和路由透明：启动、保存 Provider、刷新模型目录及测试连接只读取 `/models`，不会继续对目录中的模型自动发起推理；旧缓存没有 `probedAt` 也不补检查。表单获取目录保留原有 GET-only 行为。默认自动路由仍可使用已登记模型，无需先付费做可用性检查。

用户可以明确点击“检查模型调用（可能计费）”。操作前显示测试文本、100 模型/4 路并发、单请求 20 秒/整批 60 秒范围，说明 `max_tokens=1` 是输出请求参数，实际输入用量、费用和请求配额由 Provider 决定。停止不能撤销已发送请求或保证退费；这些非任务检查目前没有进入任务用量账本，应以 Provider 的账单为准。

支持 raw response Channel 的桌面后端使用 `providerStream(req, signal)` 读取普通 JSON，探测 payload 没有 `stream:true`。单请求 timer 覆盖响应头和完整正文。任何单次超时、整批预算耗尽或用户停止都会 abort 整批并停止领取后续模型；旧 buffered 后端只能结束等待和后续调度，不冒充其请求已取消。原生取消 RPC 回执本身仍不是连接已释放的证据，需要另行观察实际 socket 终态。

结果分为 HTTP 成功、404/型号缺失、未知、未发起，分别保存数量与首个 stopReason。HTTP 成功只表示完整读取后收到 2xx，不证明模型质量、工具能力或完整任务可用；限流、服务错误、超时或取消不会被写成成功。统计满足 `probed=ok+missing+unknown`、`total=probed+notProbed`，本批最多 100 个；未知及未发起的模型不会从候选中隐藏。旧无统计缓存明确标为历史记录，不能表示所有模型可用。

配置或目录变化使旧检查失效，旧结果不写回，也不自动对新配置追加推理。刷新和测试连接共用最新目录请求序号，两个 GET 逆序返回时只有最新请求写缓存；配置改变后的旧连接结果返回 `stale`，UI 不用它覆盖“已保存”提示。损坏的新统计会整组丢弃检查时间、隐藏项、suspicious 和 summary，避免矛盾状态被当成证据。

已登记模型来自能力矩阵并参与自动路由；仅在目录发现的型号用于手动锁定，锁定只补入当前任务，不修改保存配置。当前目录里的 404/型号缺失记录只影响手动下拉，**不会排除已登记模型的自动路由**；实际任务仍按运行时错误和 Provider 健康状态处理。这项边界已在 UI 和测试中写明，不将目录检查当成路由的强制门槛。
