# UI 布局 V3（M9 实现依据）

依据：用户 2026-10-03 给出的 V3 布局（双层侧栏 + 主区 + 按需右侧面板）。品牌规则以 `docs/BRAND.md` 为准，计数口径沿用 `docs/UI_LAYOUT_SPEC.md`。第 10 节是需要你确认的取舍，确认前按「默认」一栏实现。

约定：
- 尺寸单位 px，都是「建议」值（品牌板没有规定尺寸）。间距只用 4 的整数倍（Tailwind 默认刻度，`tests/ui-lint.test.ts` 检查）。
- 颜色只用 `--eg-*` 变量和由它们映射的语义色（`foreground`、`muted-foreground`、`border`、`accent` 等），不引入新色。
- 图标全部用 Lucide（`lucide-react` 0.469.0，下文图标名已在依赖里核对存在），不用 emoji。草图里的 🏠📁🕐⚙️ 只表示含义。
- 状态一律用「图标形状 + 文字」表达，颜色只做辅助（BRAND.md 4.3、12-2）。

| 内容栏 | 240，可整栏收起 | `surface-2` | 右侧 1px `border` |
| 主区 | 余下宽度 | `surface` | — |
| 右侧面板 | 320，按需出现（第 7 节） | `surface-2` | 左侧 1px `border` |

### 1.1 图标栏

- 纵向：上内边距 12，项目间距 4；五个导航项在上，头像在最下，下内边距 12。
- 每项 48×48，在 60 宽里水平居中，圆角 `rounded-md`（8）。内容上下排列：图标 20，间距 4，名称 12（`text-xs`）。
- 名称必须显示：选中态的红色图标在选中底上只有 3.06:1，只够图形用，BRAND.md 4.3 要求选中项同时有文字。
- 默认：图标和名称 `muted-foreground`。悬停：底色 `surface`，文字 `foreground`。选中：底色 `selected-bg`，图标 `east-red`，名称 `foreground`，`aria-current="page"`。键盘焦点：`--eg-focus-ring`。

| 顺序 | 名称 | 图标 | 点击后 |
|---|---|---|---|
| 1 | 工作台 | `House` | 默认选中。内容栏显示「项目」「最近」两组 |
| 2 | 新任务 | `SquarePen` | 动作，不改变选中项：新建空会话（沿用当前项目，见 1.3） |
| 3 | 项目 | `Folder` | 内容栏顶部是「新建项目」按钮，下面是全部项目，末尾「已归档」分组（默认收起） |
| 4 | 历史 | `History` | 内容栏显示全部会话和目标，按今天 / 昨天 / 7 天内 / 更早分组，可搜索 |
| 5 | 设置 | `Settings` | 内容栏显示设置分类（第 8 节），主区显示所选子页 |

- 底部头像：32 的圆形，`CircleUser` 图标，`muted-foreground`。本机应用没有账户，只作占位，不可点、不进 Tab 顺序（第 10 节第 9 条）。
- 浏览器模式：头像上方显示不可点的「模拟」小标（`text-xs`），如实标明不是真实后端。
- 再点一次已选中的导航项：收起或展开内容栏（1.3）。

### 1.2 内容栏

左右内边距 12（顶行 16）。自上而下：

| 行 | 规格 |
|---|---|
| 顶行 | 高 80，左右内边距 16，两端对齐。左：组合 Logo `logo-dark-transparent`，显示宽 160（高约 52，BRAND.md 8.2-3 的下限），不用文字重打字标，不可点。右：搜索按钮 32×32，`Search` 16，`aria-label="搜索"` |
| 搜索框 | 点搜索后出现在顶行下方，高 32，`text-xs`，自动聚焦。只过滤当前内容栏列表：工作台、历史按项目 / 目标 / 会话名称，「项目」视图按项目名，设置按分类名。Esc 或清空后收起，焦点回到搜索按钮 |
| 新任务 | 高 36，整宽，`border` 描边，`rounded-md`，`SquarePen` 16 + 「新任务」`text-sm`，悬停底色 `surface`；与图标栏第 2 项同一动作 |
| 分组标题 | 高 32，`text-xs` `muted-foreground`，整行是按钮。左：`ChevronRight` 12（展开时旋转 90°）+ 「项目」/「最近」；收起时右侧显示条数 |
| 列表行 | 高 48，两行，`rounded-md`，左右内边距 8。左：类型图标 16，与第一行对齐（项目 `Folder`，目标用 2.4 的状态图标，会话 `MessageSquare`）。第一行：名称 `text-sm`。第二行：路由摘要 `text-xs` `muted-foreground`。两行都单行截断，完整内容放 `title` |
| 嵌套行 | 项目下的目标、会话：左内边距 32（比上级多 24，图标与上级名称对齐），其余同列表行 |
| 选中行 | 底色 `accent`（即 `selected-bg`），文字 `foreground` |
| 悬停 / 键盘聚焦行 | 底色 `surface`；右侧出现「更多操作」按钮 24×24（`Ellipsis` 16），菜单同 1.4。不悬停时隐藏，不计入首屏控件 |

顶行的尺寸来自 Logo 安全区：实测 `logo-dark-transparent.png` 宽 679，字标大写 E 高 55，缩到 160 宽约 13；上下各留 14、与搜索按钮间约 15，都不小于 13（BRAND.md 8.2-2）。

行改成两行，是因为单行放不下：内容栏可用文字宽约 175（嵌套行约 150），单行时名称只剩 4–5 个字。两行时名称约 12 个字，路由摘要约 14 个字。

路由摘要（第二行）：

| 行 | 内容 | 例 |
|---|---|---|
| 项目 | 生效的路由偏好 + 本月节省比例 | 「平衡 · 省 40%」；偏好来自哪一层放悬停提示（如「沿用全局设置」）；本月没有数据时只写偏好 |
| 目标 | 状态文字 + 这个目标累计节省 | 「进行中 · 省 $0.40」「等你确认 · 省 $0.12」 |
| 会话 | 主要模型 + 这个会话节省 | 「kimi-k3 · 省 $0.12」；用了几个模型时「3 个模型 · 省 $0.35」；正在执行时前面加「进行中 · 」 |

节省的口径见 5.1：大于 0 写「省 $x」，等于 0 不写，小于 0 如实写「多花 $x」；不足一分写「省 <$0.01」；缺单价时不写金额，只留模型名或偏好。悬停提示写明「和最强模式相比，按官方标价估算」。草图里的「balanced」统一用界面已有的中文标签：省钱 / 平衡 / 最强（`RoutingSettings.tsx`）。

### 1.3 内容栏收起、展开

- 整栏：再点一次已选中的导航项，或按 ⌘B（Windows / Linux 为 Ctrl+B）。收起后内容栏宽 0，主区变宽；状态存进设置，重启后保留。宽度过渡 150ms，「减少动态效果」打开时不做过渡。
- 窗口宽度 < 1180（60 + 240 + 320 + 560）时打开右侧面板：内容栏先自动收起，保证主区不小于 560；关闭面板后恢复原状态。窗口最小 960 时主区为 580。
- 图标栏一直显示，内容栏收起时选中项的高亮不变。
- 分组：点「项目」或「最近」标题展开 / 收起。标题是按钮（`aria-expanded`、`aria-controls`），默认都展开，两组状态各自存进设置。
- 「项目」组：未归档的项目，按最近更新排序。没有项目时显示一行纯文字「还没有项目」（不是链接，不计入首屏控件）；新建项目在图标栏「项目」视图里。
- 「最近」组：最近更新的 20 个会话和目标，不分项目；超过时末尾是「查看全部」，跳到「历史」视图。都没有时显示「还没有任务」。
- 点项目行：展开 / 收起它下面的目标和会话（即草图里的「任务」，按最近更新排序，最多 5 条，超出时末尾「全部 N 条」），同时设为当前项目：之后的新任务、新目标归入这个项目，输入框占位文字变成「在「项目名」里描述你的任务...」，标签行出现「项目名 ×」，点 × 取消。
- 点目标行、会话行：在主区打开（2.3、2.2），不改变展开状态。

### 1.4 右键菜单

右键、Shift+F10 或菜单键打开，和行上的「更多操作」是同一个菜单。归档、删除这类不常用操作都放在这里，不占首屏控件位。

| 对象 | 菜单项 |
|---|---|
| 项目 | 编辑项目… / 归档（已归档时为「取消归档」）/ 删除项目… |
| 目标 | 开始、暂停或继续（按状态，终态时没有）/ 放弃目标… / 删除目标… |
| 会话 | 删除会话…（依赖第 10 节第 4 条的会话持久化） |

带「…」的项先弹确认对话框，只有两个按钮：确认按钮 `east-red` 底白字（5.44:1），「取消」默认聚焦，Esc 等于取消。

| 操作 | 对话框文字 | 数据 |
|---|---|---|
| 删除项目 | 「删除「名称」？会一并删除 N 个目标、K 个会话和 M 条记忆。」数量为 0 的项省略 | 软删除（`deleted_at`），连带目标、会话和记忆；数量来自 `useProjects.requestDelete`（M8 已实现目标和记忆，会话随迁移 5 加入） |
| 放弃目标 | 「放弃这个目标？已完成的轮次会保留，之后不能再继续。」 | 状态改为已放弃，保留历史 |
| 删除目标 | 「删除这个目标？它会从列表里移除，记录仍保存在本机。」 | 软删除 |
| 删除会话 | 「删除这个会话？它会从列表里移除，记录仍保存在本机。」 | 软删除 |

软删除的记录不再显示，也不再进入提示词，但仍在本机数据库里；彻底清除不在 M9 范围。

## 2. 主区

### 2.1 首屏（新建空会话）

- 沿用现在的三行网格（`grid-rows-[2fr_auto_3fr]`），内容最宽 768（`max-w-3xl`），左右内边距 32。
- 欢迎语「你好，今天想创造什么？」：`font-display` `text-3xl`（30）`font-semibold`，下距输入框 32。
- 输入框见第 3 节。
- 快捷 chips：在输入框下方 24，横排可换行，间距 16。外观是文字链接（草图要求「非按钮」）：`text-sm` `muted-foreground`（5.98:1），无边框无底色；悬停变 `foreground` 并加下划线；键盘焦点用 `--eg-focus-ring`。
- 语义仍用 `<button>`：点了只把文字填进输入框并聚焦，不提交、不跳转；用 `<a>` 会被读屏软件当成链接。
- 文案按 V3：「整理这个文件夹的文件」「读一下这份文档，总结要点」「帮我查一下这段代码为什么报错」，填入的文字与显示的一致。`tests/ui-home.test.tsx` 的期望文字随之更新。

### 2.2 会话

- 消息流居中，最宽 768；输入框固定在底部，和首屏是同一个组件。
- 每轮回答自上而下：正文 → 成果块（有交付物时，沿用 `AssistantTurn` 的「成果」块）→ 权限确认（沿用 `ConfirmPrompt`，留在消息流里）→ 折叠路由行（5.2）。
- 成果块列出本轮写入、移动、删除的文件（取自工具调用记录）。文件名可点，在右侧面板预览（第 7 节）；末尾是「查看改动（N 个文件）」。
- 不再分「普通 / 专家」两套主区：`TaskCanvas`（可拖拽排序的卡片画布）下线，专家模式只决定浮层里显示多少细节（7.3）。

### 2.3 目标详情

入口：内容栏的目标行；或在「+」菜单勾选「目标」后提交，新建目标并打开这一页。

| 区块 | 规格 |
|---|---|
| 标题 | 目标描述，`text-xl` `font-semibold`，可多行 |
| 状态行 | `text-xs` `muted-foreground`：状态图标 + 状态文字 · 第 N 轮 · 模型调用 12 / 50 · 所属项目 · 路由摘要（如「3 个模型 · 省 $0.40」） |
| 主按钮 | 只有一个，随状态变化：未开始「开始」，进行中「暂停」，已暂停「继续」，终态没有。「放弃目标…」「删除目标…」在标题右侧的「更多操作」里（同 1.4） |
| 轮次列表 | 按时间顺序，最新一轮默认展开，其余收起。每轮标题「第 N 轮 · 标题」+ 状态图标和文字。展开后是步骤（图标 + 文字）、判定（「规则判定：已完成」「Jev 判定：未完成（置信度 0.82）」「你确认：已完成」「执行出错」）和这一轮的折叠路由行（5.2） |
| 等你确认 | 最后一轮判定为 uncertain 时，轮次列表上方出现提示条：`CircleHelp` + 「AI 声称完成，但无实据」+ 原因；两个按钮「确认已完成」「继续下一轮」，分别调 `useGoals.resolve(id, "done")` 和 `resolve(id, "continue")`。不自动进入下一轮，不自动收尾 |
| 失败 | 状态行下写明原因，文案取自 `goal.ts`：「模型调用次数用完」「校验连续 3 轮没通过」「轮数达到上限（100 轮）」 |

M9 把详情页和按钮接到 M8 的 store，「开始」在 M9 只改状态；自动多轮循环、每轮调 `checkDoneWithEvidence`、用量上限检测在 M10 接上。

### 2.4 状态图标

与任务卡片（`task/status.tsx`）一致，新增「未开始」「已暂停」两种：

| 状态 | 图标 | 颜色 |
|---|---|---|
| 未开始 | `CircleDashed` | `muted-foreground` |
| 进行中 | `LoaderCircle`，转动；「减少动态效果」打开时不转 | 跟随文字 |
| 等你确认 | `CircleHelp` | 跟随文字 |
| 已暂停 | `CirclePause` | `muted-foreground` |
| 已完成 | `CircleCheck` | `foreground`，不用绿色（BRAND.md 4.3） |
| 失败 | `CircleX` | `east-red`，同时写原因（红色在 `surface` 上只有 2.34:1，不能只靠颜色） |
| 已放弃 | `CircleSlash` | `muted-foreground` |

「等你确认」不是单独的状态：目标仍是「进行中」，只是最后一轮判定为 uncertain（M8 的 `goalPhase` 返回 `awaiting_user`）。

### 2.5 项目概览

- 在图标栏「项目」视图里点项目行，主区显示概览：名称、描述、生效的路由偏好和来源（如「省钱（来自项目）」，来源标签取自 `PREFERENCE_SOURCE_LABEL`）、项目指令（默认收起）、上下文文件夹、目标与会话列表（同内容栏的行）、记忆条数。右上角是「编辑」。
- 工作台里点项目行只展开并设为当前项目（1.3），不切换主区。
- 新建和编辑共用一个对话框：名称（必填，1–60 字）、描述、项目指令、上下文文件夹（系统对话框选择，可移除）、路由偏好（沿用全局 / 省钱 / 平衡 / 最强）。保存失败时，把 store 返回的中文原文显示在对应字段下。
- 已归档的项目只读：标题旁 `Archive` 图标 +「已归档」，主按钮是「取消归档」；界面不提供新建目标、新任务的入口（M8 后端仍允许）。

## 3. 输入框

外框：最宽 768，`rounded-lg`（12），描边 `east-red/40`，底色 `surface-2`；聚焦时显示 `--eg-focus-ring`（BRAND.md 第 7 节实现建议 2）。框内的图标都在 `surface-2` 上，对比度按这个底色算。内部三行：

| 行 | 规格 |
|---|---|
| 标签行（可选） | 有当前项目、你为这个任务选的工作目录（默认的 `~/Downloads` 不显示）、附件、非快速模式或多 Agent 时才出现，内边距 8，间距 8。每个标签高 24，`text-xs`，`border`，`rounded-sm`：图标 12 + 文字 + 移除按钮（`X` 12，`aria-label="移除…"`）。例：`Folder` 项目名、`FolderOpen` 目录名（完整路径放 `title`）、`Paperclip` 文件名、`Target` 目标、`Lightbulb` 计划模式、`Users` 多 Agent |
| 文本区 | 最低 56（`min-h-input`），超过 192 后滚动；左侧 `Sparkles` 20 `china-gold`（11.43:1，图形用），左内边距 48。占位文字：默认「描述你的任务...」；有当前项目时「在「项目名」里描述你的任务...」；目标「描述要持续追求的目标...」；计划模式「描述任务，先出计划再执行...」 |
| 底行 | 高 40，左右内边距 8，下内边距 8，元素间距 8，四个元素见下表 |

| 顺序 | 元素 | 规格 |
|---|---|---|
| 1 | 添加 | 32×32 图标按钮，`Plus` 16，`aria-label="添加"`，打开第 4 节菜单 |
| 2 | 权限模式 | 胶囊，高 32，最宽 128，`border`，`rounded-md`，`text-xs`：档位图标 16（颜色见第 6 节）+ 档位名 + `ChevronDown` 12。沿用原生 `select` 覆盖层（`aria-label="权限"`，`title` 为现有说明），语义不变 |
| — | 空白 | `flex-1`，把后两项推到右侧 |
| 3 | 自动路由 | 胶囊，规格同上，最宽 160：`Route` 16（锁定时 `Lock`）+ 模式名 + `ChevronDown` 12。是按钮（`aria-haspopup="menu"`），可见文字就是可访问名称；放不下时截断，全名放 `title`；打开第 5 节下拉 |
| 4 | 发送 | 32×32，`east-red` 底、白色 `ArrowUp` 16（5.44:1），`aria-label="提交任务"`；输入为空时禁用 |

- 草图里的 🎤 不放（第 10 节第 7 条）。
- 键盘：Enter 换行（不变）；⌘↩ / Ctrl+Enter 发送（新增）。
- Tab 顺序与视觉一致：标签行的移除按钮 → 文本区 → 添加 → 权限 → 自动路由 → 发送。
- 权限图标从现在的 12 放大到 16，颜色区别更容易看清。

## 4. 「+」菜单

点「添加」向上弹出，与按钮左对齐。宽 256，底色 `popover`（即 `surface-2`），1px `border`，`rounded-md`，内边距 4。菜单项高 36（带说明时 48），左右内边距 8，图标 16 + 文字 `text-sm`，间距 8；说明在第二行，`text-xs` `muted-foreground`；勾选项右侧 `Check` 16。顶部是不可点的组标题「添加」（`text-xs` `muted-foreground`）。键盘：上下方向键移动，Enter 选中，→ 打开子菜单，← 返回上级，Esc 关闭并把焦点还给「添加」。

```
添加
├ 文件和文件夹 ›   文件… / 文件夹…
├ 工作目录 ›       项目文件夹、最近用过的目录 / 选择其他文件夹…
├ 目标             设置持续追求的目标
├ 计划模式         先出计划，你确认后再执行
├ 多 Agent 协同
├ ───
└ 插件 ›           文件系统（内置）/ 已登记的 MCP 服务器 / 管理插件…
```

## 5. 自动路由下拉

点路由胶囊向上弹出，与胶囊右对齐，宽 288，样式和键盘同第 4 节。

```
路由模式
├ 自动（推荐）     Jev 决策 · 当前按「平衡（来自全局设置）」   ← 默认
├ 省钱模式         同样能做好时选更便宜的
├ 最强模式         质量优先，不看价格
├ ───
├ 手动锁定 ›       Kimi k3 / Claude Opus 5.5 / Claude Sonnet 5 / DeepSeek v4.1 Flash / …
├ ───
└ 本月省了约 $X.XX                                       ← 只读
```

| 菜单项 | 类型 | 语义 |
|---|---|---|
| 自动（推荐） | 单选，默认 | 任务层不设偏好，按 任务 > 目标 > 项目 > 全局默认 取值（M8 的 `resolveRoutingPreference`），由决策层（云端 Jev → 本地决策模型 → 规则引擎）选模型。说明行写当前生效的偏好和来源 |
| 省钱模式 / 最强模式 | 单选 | 这个任务的偏好设为 `economy` / `best`，覆盖目标、项目和全局 |
| 手动锁定 | 子菜单 | 按 Provider 分组列出能用的模型（已配 Key 的官方 Provider + 自定义中转站的 `/models` 缓存），不写死名单。选中后整个任务锁定这个模型、不再自动降级，子菜单顶部写明这一点（BRAND.md 12-3）。胶囊变成「锁定 · 模型名」 |
| 本月省了约 $X.XX | 只读 | 口径见 5.1；有调用缺单价时加一行「N 次调用没有单价，未计入」。点击跳到设置 › 个人 › 使用情况 |

- 打分算法、权重、降级链和 `jev-config.ts` 都不改。延迟权重、成本上限、超时仍在设置 › 模型与路由 › 路由偏好。
- 运行中的干预（「只改下一次调用」，`Intervention.tsx`）在 5.2 的浮层里，不在这个下拉。
- 胶囊文字：自动路由 / 省钱模式 / 最强模式 / 锁定 · 模型名。

### 5.1 「省了多少」的口径

- 每次模型调用记下实际模型、输入和输出 tokens、基准模型。基准模型 = 同一任务类型、同一批可用模型里，规则引擎按「最强」偏好排第一的模型（本地计算，不多调 Jev）。
- 节省 = 基准模型按这次调用的 tokens 计价 − 实际模型计价。tokens 用实际调用的数；不同模型分词不同，所以金额前写「约」。
- 单价放在新文件 `config/model-prices.json`：每个模型的输入、输出单价（每百万 tokens）、币种、官方价目页链接、核对日期。不改 `model_profiles.json`，打分用的 `cost_tier` 不动。人民币价按文件里写明日期的固定汇率折成美元。
- 核对不到官方价的模型不填单价，不估。缺单价的调用不计入金额，下拉和使用情况页写出条数。自定义中转站默认不计，用户在中转站设置里填了单价才计。
- 统计按自然月、本地时区。调用记录持久化到 SQLite（迁移 5，第 11 节）；现在的用量只在内存里（`usageTotals`），重启就没了。
- 金额在显示时按当前价目表计算，不存进数据库；价目表更新后历史金额跟着变，悬停提示写「按当前价目表估算」。

### 5.2 回答下方的折叠路由行

- 位置：每轮回答（目标的每一轮也一样）的成果块下方，`text-xs` `muted-foreground`。整行是一个按钮（`aria-expanded`、`aria-haspopup="dialog"`），悬停变 `foreground`。
- 文案：「使用 kimi-k3 · 省 $0.12 · 为什么选它」。几个模型时沿用现有的「使用 kimi-k3（共 3 个模型）」；缺单价时去掉金额；手动锁定时「手动锁定 kimi-k3 · 查看详情」；有降级时在金额后接现有文案（如「因超时降级 1 次」）。耗时和 tokens 从折叠行移到浮层。
- 点开是主区内的浮层，不占固定空间：锚在这一行下方，下方放不下时翻到上方；盖在消息流上，不推开下面的内容。宽同消息列（最宽 768），最高为视口的 60%，超出部分内部滚动。底色 `popover`，1px `border`，`rounded-md`，内边距 16，`role="dialog"`，`aria-label="路由决策"`。
- 关闭：Esc、点浮层外、再点这一行；关闭后焦点回到这一行。同一时间只开一个。
- 浮层有两个标签页：
  - 路由决策：任务类型、需要的能力、候选模型和理由、降级与失败记录、做决策的是哪一级（云端 Jev / 本地决策模型 / 规则引擎）、生效偏好和来源、这次调用与基准模型的价格对比。任务进行中时这里有干预：「只改下一次调用」「整个任务锁定」（沿用 `Intervention.tsx`）。专家模式打开时多显示内部评分、四项权重和成本档。
  - 执行过程：时间线（沿用 `Timeline.tsx`），每一步的模型、工具、tokens、耗时，降级的那一步标成提醒；成本档只在专家模式显示；多 Agent 时含子任务进度（`SubAgents.tsx`）。
- 现在的 `RouteLine.tsx` 是原地展开，M9 改成浮层，测试随之更新。
